감시 대상·3단계 경고 시스템

마을을 지키기 위한 명시적 정책. 위험을 알고 들어오는 특정 사용자에 대한 감시 강화와, 해킹 시도 발생 시 3단계 경고 후 강퇴까지의 절차를 정리했습니다. 이 정책은 광장 약속의 부속 문서로 사이트에 공개됩니다.

1. 감시 대상자 목록 (Watchlist)

운영자가 사전에 위험을 인지하고 있는 사용자. 이들이 가입·로그인·글쓰기 활동을 할 때 관리자에게 즉시 알림이 가고, 모든 행동이 자세히 로그됩니다.

감시 강화 대상

경계 경보 자동 발령 명단

이우주 학생
이규민 학생

위 사용자가 닉네임·이름·이메일·휴대폰 끝 4자리 등으로 식별되어 가입 시도하거나 로그인하면 즉시 관리자에게 경계 경보가 발령됩니다. 가입 자체는 막지 않지만, 모든 행동이 상세 로그에 기록되고 의심 행동 발견 시 1차 경고가 즉시 발동합니다.

감시 대상 식별 방법

이름만으로는 식별이 어렵습니다 (동명이인 가능). 다음 조합으로 매칭:

  • 이름 + 학년: "이우주 (중2)" 같은 조합
  • 이메일: 알려진 이메일 주소
  • IP 대역: 같은 학원·학교에서 접속하는 IP
  • 닉네임 유사성: "wooju", "이우주", "lee_w" 등 유사 패턴
  • 기기 지문: 브라우저 fingerprint (보조 단서)
주의 — 신중하게 적용 동명이인 가능성이 있으므로 "이름만 일치"로는 자동 차단 X. 운영자가 알림을 받고 직접 확인 후 조치. 무고한 학생이 오해받지 않게 합니다.

감시 대상 추가·해제 절차

  • 운영자만 추가·해제 가능
  • 관리자 대시보드 → 보안 → 감시 대상 관리
  • 추가 시 사유 명시 (예: "타 사이트 해킹 전과")
  • 1년마다 자동 재검토 — 1년간 문제 없으면 해제 검토

2. "해킹 시도"의 정의 — 무엇이 경고 대상인가

모호한 기준은 분쟁의 원인입니다. 어떤 행동이 "해킹 시도"로 간주되는지 명확히 정합니다.

행위 카테고리 구체 예시 심각도
인증 우회 시도 관리자 페이지 URL 직접 접근, 비밀번호 무차별 대입(5번 이상), 다른 사람 계정으로 로그인 시도 중대
스크립트 주입 글이나 댓글에 <script>, onerror=, javascript: 등 삽입 시도 중대
SQL 인젝션 시도 입력 폼에 ' OR 1=1 --, UNION SELECT 등 SQL 패턴 중대
비정상 API 호출 일반 사용자가 못 보는 API 엔드포인트 직접 호출, 다른 사용자 ID로 데이터 요청 중대
대량 자동화 분당 30건 이상 글·댓글 등록, 매크로로 보이는 패턴 경고
도배·스팸 같은 내용 반복, 의미 없는 문자열, 외부 광고 링크 경고
개발자 도구 비정상 사용 관리자 권한 변수 조작 시도, 로컬스토리지 임의 변경, 콘솔에서 fetch로 직접 API 호출 경고
다중 계정 같은 IP·기기에서 5개 이상 계정 생성 주의
경고 회피 경고 받은 후 다른 계정으로 가입, IP 우회 시도 즉시 강퇴
판단 원칙 "심각도 중대"는 1번 발견 시 곧바로 2단계 이상 경고. "경고"는 1단계부터. "주의"는 관리자 알림만, 별도 경고는 X.

3. 3단계 경고 시스템

1
1차 경고
노란 카드

해킹 시도가 처음 감지되면 사용자 화면에 경고창이 뜨고, 행위는 차단됩니다. 관리자에게도 알림이 가서 어떤 행위였는지 확인합니다.

제한: 24시간 글쓰기 정지
알림: 사용자에게 + 관리자에게
기록: 영구 로그 남김
2
2차 경고 — 마지막
마지막 카드

같은 사용자가 두 번째로 시도하면 "마지막 경고"가 발동됩니다. 사용 권한이 7일간 정지되고, 한 번 더 시도하면 강퇴라는 사실을 명확히 알립니다.

제한: 7일 전체 정지 (로그인 가능, 글쓰기 X, 댓글 X)
알림: 사용자에게 + 관리자에게 + (학생이라면) 학부모 통보 옵션
기록: 영구 로그 + "마지막 경고" 플래그
3
3차 — 강퇴
빨간 카드

세 번째 시도 시 영구 강퇴. 계정 삭제·IP 차단·이메일 등록 불가 처리. 강퇴 사유는 관리자 로그에 영구 보존됩니다.

제한: 영구 차단 (재가입 불가)
알림: 사용자에게 + 관리자에게 + (학생이라면) 학부모 통보 + 필요시 학교·경찰 신고
기록: "강퇴 명단"에 영구 보존

예외 — 즉시 강퇴 케이스

다음은 1·2단계 없이 곧바로 3단계(강퇴):

  • 관리자 계정 탈취 시도 성공한 경우
  • 데이터베이스 또는 시스템 파일 손상 시도
  • 이미 강퇴된 사람이 다른 계정으로 재가입한 경우
  • 다른 사용자의 개인정보를 훔치려 한 경우
  • 형사 처벌 대상이 명백한 행위 (위협·협박 등)

5. 기술 구현 — 어떻게 작동하나

데이터 구조

// Cloudflare D1 테이블 설계 // 감시 대상 명단 CREATE TABLE watchlist ( id INTEGER PRIMARY KEY, name TEXT, grade TEXT, -- "중2" 같은 학년 email TEXT, ip_pattern TEXT, -- "211.43." 같은 IP 대역 nickname_pattern TEXT, -- "wooju|이우주" 같은 정규식 reason TEXT, -- 등록 사유 added_by TEXT, -- 운영자 added_at DATETIME, active BOOLEAN DEFAULT 1 ); // 위반 기록 (영구 보존) CREATE TABLE violations ( id INTEGER PRIMARY KEY, user_id INTEGER, ip TEXT, device_fingerprint TEXT, violation_type TEXT, -- 'auth_bypass', 'xss', 'sql_injection' 등 detail TEXT, -- 실제 시도 내용 severity TEXT, -- 'severe', 'warning', 'notice' stage INTEGER, -- 1, 2, 3 detected_at DATETIME, acted_at DATETIME, resolution TEXT -- 'warn', 'suspend7', 'ban', 'false_positive' ); // 사용자 상태 ALTER TABLE users ADD COLUMN warning_count INTEGER DEFAULT 0; ALTER TABLE users ADD COLUMN suspended_until DATETIME; ALTER TABLE users ADD COLUMN banned BOOLEAN DEFAULT 0; ALTER TABLE users ADD COLUMN watchlist_match TEXT;

감지 로직 (의사 코드)

// Cloudflare Workers에서 async function checkAction(user, action, content) { // 1. 감시 대상 매칭 확인 const onWatchlist = await isOnWatchlist(user); if (onWatchlist) { notifyAdmin('감시 대상 활동', user, action); } // 2. 해킹 시도 패턴 검사 const violations = detectViolations(content, action); if (violations.length === 0) return { ok: true }; // 3. 심각도에 따라 단계 결정 const severity = getMaxSeverity(violations); let newStage; if (severity === 'severe') { // 중대 위반: 1단계라도 곧바로 2단계로 newStage = Math.max(user.warning_count + 1, 2); } else { newStage = user.warning_count + 1; } // 4. 단계별 조치 if (newStage === 1) { suspendWriting(user, '24h'); sendWarning(user, '1차 경고'); } else if (newStage === 2) { suspendAll(user, '7d'); sendWarning(user, '마지막 경고'); notifyParents(user); // 학생이면 } else if (newStage >= 3) { banUser(user, '영구'); sendWarning(user, '강퇴'); notifyParents(user); } // 5. 영구 기록 await logViolation(user, violations, newStage); await notifyAdmin('위반 감지', user, newStage); }

알림 채널

  • 관리자 이메일 — 모든 단계의 알림 (jinwooshon@gmail.com)
  • 관리자 대시보드 — 실시간 알림 배너 + "최근 위반" 패널
  • (선택) 카카오톡 알림 — 카카오 알림톡 API 연동 시
  • 학부모 통보 — 2차·3차 단계, 가입 시 학부모 이메일 받아둬야 가능

6. 공정성·이의 신청

억울하게 경고받을 가능성도 있어요. 공정성을 위해 다음을 마련합니다.

오탐 방지

  • 1차 경고 발동 시 자동 알림 + 관리자가 30분 안에 확인
  • 오탐으로 판명되면 즉시 복구 + 사과 메시지
  • AI 모더와 별개의 규칙 기반 감지 → 두 시스템 모두 동의해야 발동

이의 신청 절차

  • 경고 받은 사용자는 24시간 안에 이메일로 이의 신청 가능
  • 관리자가 7일 안에 검토·답변
  • 오탐 확인 시 경고 취소 + 카운트 복구
  • 3차 강퇴자도 1회 이의 신청권 보장

학생 보호 원칙

  • 실명 공개 X — 위반 사실을 다른 사용자에게 공개하지 않음
  • 학교 통보는 신중히 — 형사 처벌 대상 아니면 학교 X, 학부모만
  • 회복 기회 — 강퇴자도 1년 후 본인 신청 시 재검토
  • 교육적 관점 — 학생이 호기심으로 시도하는 경우, 강한 처벌 전에 대화 우선
교육적 접근 이우주·이규민 학생이 들어왔는데 실제 해킹 시도가 발견됐다면, 1차 경고와 함께 "왜 그랬는지 한 줄 답해줘"라는 메시지를 보내볼 수도 있어요. 호기심에서 비롯된 시도라면 광장의 자원이 되어줄 수도 있습니다. 처벌만이 답은 아닙니다.

7. 정책 공개·고지

이 정책은 비밀이 아니라 마을의 약속입니다. 사이트에 명시적으로 공개합니다.

공개 위치

  • 회원가입 시 "약관·운영 정책 동의" 체크박스에 링크
  • 광장 약속 페이지의 부속 문서로
  • 관리자 페이지에서도 조회 가능

가입 시 동의 받기

가입 폼에 다음 체크박스 추가:

8. 관리자 운영 매뉴얼

매일 (1분)

  • 대시보드 → 보안 알림 새 항목 없는지 확인

매주 (10분)

  • 지난주 위반 기록 검토 (오탐 없었는지)
  • 감시 대상자 활동 패턴 검토
  • 새로운 공격 패턴 발견 시 감지 규칙에 추가

경계 경보 받았을 때

  1. 침착하게 알림 자세히 보기 (어떤 시도였는지)
  2. 해당 사용자의 다른 활동 확인 (정상 글도 있는지)
  3. 오탐 가능성 판단 — 의심스러우면 복구
  4. 분명한 시도면 단계 진행 (자동으로 발동돼 있음)
  5. 중대 케이스는 증거 보존 (스크린샷, 로그)
마지막 한 가지 이 정책은 마을을 보호하기 위한 것이지, 처벌하기 위한 것이 아닙니다. 모든 경고는 "다시 잘 들어오라"는 손짓이어야 합니다. 학생이 호기심에 한 일과 악의적인 공격을 구분하는 것이 운영자의 가장 어려운 일이에요. 망설여지면 처벌보다 대화부터.
