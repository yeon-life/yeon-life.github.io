마을을 지키는 일 — 보안 대책

해킹은 한 번 일어나면 회복이 어렵습니다. 다행히 연라이프는 GitHub Pages + 정적 사이트라 기본 보안이 이미 강한 편이에요. 그래도 마을이 자라면서 챙겨야 할 일들이 있습니다. "어디가 약한가, 어떻게 막을까, 일이 생기면 어떻게 할까"를 정리합니다.

한 페이지 결론

지금 당장 5가지만 챙기면 80%는 안전

1. 관리자 비밀번호 강화 + 2단계 인증

2. API 키 절대 브라우저 노출 X (Cloudflare Workers로 가렸음)

3. 모든 사용자 입력 sanitize (XSS 방어)

4. 매주 자동 백업 (GitHub + Google Drive 이중)

5. Cloudflare 보안 기능 켜기 (DDoS·봇 차단, 무료)

이 다섯 가지가 갖춰져 있으면 일반적인 공격은 거의 다 막힙니다. 나머지는 마을이 커지면서 단계적으로.

01현재 보안 상태 — 약점 점검

먼저 연라이프의 현재 구조에서 어디가 강하고 어디가 약한지 솔직히 봅니다.

강한 부분 ✓

  • GitHub Pages 호스팅 — 정적 사이트라 서버 침투가 거의 불가능. SQL Injection 같은 백엔드 공격이 적용 안 됨
  • 자동 HTTPS — github.io는 기본으로 HTTPS 적용. 통신 도청 어려움
  • 인프라 보안 — GitHub의 보안팀이 인프라 관리. 작은 사이트가 직접 서버 관리하는 것보다 안전
  • 로컬 데이터 저장 — 현재 글들이 사용자 기기 localStorage에 저장. 중앙 DB 해킹으로 모든 데이터 유출되는 시나리오 X

약한 부분 ⚠

  • 관리자 비밀번호가 클라이언트 측에 있을 가능성 — 정적 사이트의 한계. JS 코드에 비밀번호가 박혀 있으면 누구나 코드를 보고 알아낼 수 있음. 즉시 확인 필요
  • Gemini API 키 사용자 입력 방식 — 현재는 각 사용자가 자기 키를 입력하는 구조. 향후 Cloudflare Workers로 옮길 때 노출 위험 처리 필요
  • XSS 방어 미확인 — 사용자가 글에 <script> 같은 악성 코드 삽입 가능성. 다른 사용자가 그 글 보면 코드 실행됨
  • 봇·스팸 방어 없음 — 자동화된 도배 글 등록에 무방비. 운영 원칙에는 있지만 자동 차단 X
  • 백업 정책 없음 — GitHub 저장소가 사라지거나 손상되면 복구 어려움

02연라이프에 실제로 닥칠 수 있는 위협 8가지

위험도는 가능성 × 피해로 평가했습니다.

위험 높음

① 관리자 계정 탈취

관리자 비밀번호가 노출되거나 추측당하면 사이트 전체 통제권을 잃습니다. 화두 변경·글 삭제·악성 콘텐츠 게시·결제 정보 변경 가능.

방어 — 강력한 비밀번호 + 2단계 인증 + 로그인 시도 제한 + 관리자 비밀번호를 클라이언트 코드에서 제거
위험 높음

② API 키 유출

Gemini·Claude API 키가 브라우저에 노출되면 누군가 훔쳐서 무한 호출 → 한 달에 수백만원 청구서. 또는 키로 다른 부정한 일에 사용.

방어 — Cloudflare Workers 서버 환경변수에만 키 저장. 브라우저는 키 모름. 사용량 한도 자체 설정.
위험 높음

③ XSS (Cross-Site Scripting)

악성 사용자가 글에 <script> 코드 삽입 → 다른 사용자가 그 글 보면 코드가 그 사용자 브라우저에서 실행됨 → 쿠키 탈취·악성 사이트 이동.

방어 — 모든 사용자 입력을 HTML 이스케이프 처리 (DOMPurify 라이브러리). innerHTML 대신 textContent 사용.
위험 중간

④ 봇·자동 도배

자동화된 봇이 광고·스팸 글을 대량으로 등록. 광장의 결을 망가뜨리고 진짜 글이 묻힘. AI 모더가 도와주지만 비용도 늘어남.

방어 — Cloudflare Turnstile (reCAPTCHA 무료 대안) + 등록 속도 제한 (분당 5건 이하) + 동일 IP 차단
위험 중간

⑤ DDoS (대량 요청 공격)

누군가 사이트에 초당 수천 건의 요청을 보내 다운시킴. 정적 사이트라 GitHub Pages가 어느 정도 견디지만, 한도 초과 시 일시 차단됨.

방어 — Cloudflare 무료 플랜이 자동으로 DDoS 차단. 도메인을 Cloudflare에 연결.
위험 중간

⑥ 데이터 손실

GitHub 계정 해킹·실수 삭제·디스크 오류로 사이트와 콘텐츠 손실. 회원의 글이 사라지면 마을의 기억이 사라지는 셈.

방어 — 매주 자동 백업 (GitHub + Google Drive + 로컬 외장 드라이브). 사용자 글은 D1 DB + 매일 백업.
위험 낮음

⑦ 피싱 (사회공학 공격)

"연라이프 운영팀입니다, 비밀번호 알려주세요" 같은 가짜 메일·메시지. 운영자가 속아서 정보를 넘기는 경우.

방어 — 어떤 회사·플랫폼도 비밀번호를 묻지 않는다는 원칙 기억. 의심 메일은 무시. 도메인 확인 습관.
위험 낮음

⑧ 개인정보 유출

회원 이메일·연락처 등이 유출. 정적 사이트라 위험은 낮지만, 한국 개인정보보호법(PIPA) 위반은 큰 처벌.

방어 — 개인정보 최소 수집 원칙. 이메일은 비밀번호 분실 복구용으로만. 평문 저장 X, 해시화.

041순위 — 지금 당장 5가지

① Cloudflare 연결 (가장 큰 효과, 30분 작업)

Cloudflare를 도메인 앞단에 두면 DDoS 방어·봇 차단·SSL·캐싱이 한 번에 들어옵니다. 모두 무료.

  1. cloudflare.com 가입 → "Add a site" → y-life.kr 입력
  2. 현재 DNS 자동 스캔 → "Continue"
  3. Cloudflare가 알려주는 nameserver 두 개를 도메인 등록업체(가비아·후이즈 등)에서 변경
  4. 24시간 내 적용 → 자동으로 HTTPS·DDoS 방어 켜짐
  5. Cloudflare 대시보드 → Security → Bots → "Bot Fight Mode" ON

② 관리자 비밀번호 점검

지금 index.html 코드를 열어서 비밀번호가 어떻게 저장돼 있는지 확인하세요.

// ❌ 절대 이러면 안 됨 — 누구나 코드 보고 알 수 있음 const adminPassword = "yeon2026"; if (input === adminPassword) { ... } // ❌ localStorage에 평문 저장도 안 됨 localStorage.setItem('admin_pw', 'yeon2026'); // ✅ Cloudflare Workers 환경변수로 옮기기 // 클라이언트는 비밀번호를 보내고, Workers가 검증 후 토큰 발급 fetch('/api/admin/login', { method: 'POST', body: JSON.stringify({ password: input }) }).then(res => { /* 토큰 받음 */ });
지금 바로 확인해보세요 브라우저로 y-life.kr 열기 → F12 (개발자 도구) → "소스" 탭 → index.html → Ctrl+F로 "password" 검색 → 비밀번호 평문이 보이면 위험.

③ 매주 자동 백업

GitHub Actions로 매주 일요일 새벽 사이트 전체를 Google Drive에 백업하는 워크플로 추가.

// .github/workflows/backup.yml name: Weekly Backup on: schedule: - cron: '0 18 * * 0' # 매주 일요일 03:00 KST jobs: backup: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Zip site run: zip -r y-life-backup-$(date +%Y%m%d).zip . - name: Upload to Google Drive # rclone 또는 Google Drive Action 사용

④ DOMPurify로 사용자 입력 처리

사용자가 쓴 글을 화면에 보여줄 때 악성 코드를 제거합니다. 라이브러리 한 줄이면 됨.

<!-- HTML head에 추가 --> <script src="https://cdn.jsdelivr.net/npm/dompurify@3.0.6/dist/purify.min.js"></script> // 사용자 글 표시할 때 // ❌ 위험 postElement.innerHTML = userPost.body; // ✅ 안전 postElement.innerHTML = DOMPurify.sanitize(userPost.body);

⑤ 사이트 보안 헤더 추가

HTML head에 Content Security Policy 메타태그 추가. 외부 스크립트 실행을 제한.

<meta http-equiv="Content-Security-Policy" content=" default-src 'self'; script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://fonts.googleapis.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://cdn.jsdelivr.net; font-src https://fonts.gstatic.com https://cdn.jsdelivr.net; img-src 'self' data: https:; connect-src 'self' https://*.workers.dev https://generativelanguage.googleapis.com; ">

05중기 보완 — 한 달 안에

로그인 시도 제한

Cloudflare Workers에 카운터 추가. 같은 IP에서 비밀번호 5번 틀리면 30분 잠금.

봇 방지 — Cloudflare Turnstile

회원가입·글쓰기·댓글 등록 폼에 Turnstile 위젯 추가. 사용자에겐 거의 보이지 않지만 봇은 차단.

  1. Cloudflare 대시보드 → Turnstile → "Add Site"
  2. Site Key·Secret Key 발급
  3. 폼에 <div class="cf-turnstile" data-sitekey="YOUR_KEY"></div> 추가
  4. 제출 시 토큰 받아서 Workers에서 검증

관리자 2단계 인증 (2FA)

비밀번호만으로는 부족. Google Authenticator로 6자리 OTP 추가.

  • Workers에서 TOTP 라이브러리 사용 (otpauth 등)
  • 관리자 가입 시 QR 코드 발급 → 폰에 등록
  • 로그인 시 비밀번호 + 6자리 OTP 둘 다 입력

비밀번호 해시 저장

회원 비밀번호는 절대 평문 저장 X. bcrypt로 단방향 해싱.

// Workers에서 import bcrypt from 'bcryptjs'; // 가입 시 const hash = await bcrypt.hash(password, 12); // DB에 hash 저장 (평문 password는 버림) // 로그인 시 const match = await bcrypt.compare(input, storedHash);

06장기 강화 — 마을 커진 후

월간 보안 점검

  • Cloudflare 대시보드 확인: 차단된 봇 수, 의심스러운 트래픽
  • Anthropic 콘솔 사용량 확인: 갑작스러운 비용 급증 없는지
  • 로그인 실패 기록 확인: 비정상적 시도 패턴
  • GitHub 보안 알림 확인: 종속성 취약점, 보안 권고
  • 백업 정상 작동 확인: 매주 백업 파일이 잘 생성됐는지

보안 자체 진단 도구 활용

  • Mozilla Observatory (observatory.mozilla.org) — 사이트 보안 등급 평가, 무료
  • SSL Labs (ssllabs.com/ssltest) — SSL 설정 점검
  • SecurityHeaders (securityheaders.com) — HTTP 헤더 점검

점진적 강화 항목

  • WAF (Web Application Firewall) 규칙 추가 — Cloudflare 유료 플랜
  • 모든 외부 종속성 정기 업데이트 — Dependabot 활용
  • 침투 테스트 (1년에 한 번) — 화이트해커 무료 도구 또는 외주
  • 개인정보 처리방침·이용약관 정식 작성

07일이 생겼을 때 — 사고 대응 매뉴얼

아무리 잘 막아도 일은 일어날 수 있습니다. 발견했을 때 당황하지 않도록 단계별 대응을 정해둡니다.

1

의심 발견 — 무엇이 이상한가

평소와 다른 일이 보일 때:
  1. 이상한 글이 대량 등록 (도배 공격)
  2. 관리자 패널에 들어가지 못함 (계정 탈취 가능성)
  3. AI 비용이 급증 (API 키 유출 가능성)
  4. 방문자가 "사이트가 이상하다" 알림 (XSS 가능성)
  5. 사이트가 다운됨 (DDoS 또는 GitHub 장애)
2

즉시 격리 — 더 큰 피해 막기

  1. API 키 즉시 폐기 (Anthropic·Gemini 콘솔에서 revoke)
  2. 관리자 비밀번호 즉시 변경
  3. 의심스러운 사용자 계정 일시 정지
  4. 심각하면 Cloudflare에서 "Under Attack" 모드 켜기 — 모든 방문자에게 검증 페이지 노출
3

증거 보존 — 무슨 일이 있었나

  1. Cloudflare 로그 다운로드 (Analytics → Security Events)
  2. D1 DB 상태 스냅샷 (백업)
  3. GitHub 커밋 히스토리 확인 (누가 언제 무엇을 바꿨나)
  4. 이상한 글들 캡처
4

복구 — 정상 상태로

  1. 백업본에서 깨끗한 상태 복원
  2. 새 API 키 발급·환경변수 갱신
  3. 관리자 비밀번호 새로 설정 + 2FA 추가
  4. 잠시 가입을 닫고 점검 시간 가짐
  5. 주민에게 투명하게 알림 — 무엇이 일어났고 무엇을 했는지
5

되돌아보기 — 어떻게 다시 안 일어나게 할까

  1. 이번 사고의 진입 경로 파악
  2. 해당 약점 보완 (코드 수정·정책 추가)
  3. 유사한 약점 다른 곳에 없는지 점검
  4. 사고 대응 매뉴얼에 새 항목 추가
  5. 심각한 경우 한국인터넷진흥원(KISA) 신고

08주민의 신뢰 — 투명함이 곧 보안

기술적 보안 못지않게 중요한 것이 주민과의 신뢰입니다. 연라이프 같은 마을은 "운영자가 데이터를 어떻게 다루는지"가 곧 신뢰의 기반이에요.

마지막 한 마디

완벽한 보안은 없습니다. 다만 균형이 있습니다.

너무 강한 보안은 사용 경험을 망치고, 너무 약한 보안은 마을을 위협합니다.

연라이프 같은 작은 마을에 맞는 균형은 — 핵심 다섯 가지(관리자 인증·API 키 보호·XSS·백업·Cloudflare)는 단단히, 나머지는 마을이 자라면서 단계적으로.

가장 중요한 것은 "무엇이 정상인지 항상 알고 있는 것"입니다. 비용 패널, 회원 추이, 글 추이를 매주 5분만 봐도 이상한 일을 빨리 발견할 수 있어요.

"연라이프는 천천히 자라는 마을입니다. 마을의 안전도 천천히 단단히 자랍니다."
