4. 본문 내용 갱신 — 디자인 마무리 후 한꺼번에

색 토큰은 일괄 갱신 완료. 그러나 각 자료의 본문 내용 (예: "Claude Haiku 추천" → "하이브리드 라우팅 추천")까지 일일이 다시 쓰면 같은 작업을 여러 번 하게 됩니다. 효율을 위해 본문 내용은 디자인 마무리 후 한꺼번에 갱신하는 게 좋습니다.

그 때까지는 이 문서가 모든 결정의 단일 진실원입니다. 다른 자료를 볼 때 이 문서를 옆에 두면 어떤 부분이 갱신 대상인지 알 수 있습니다.

5. 호환성 약속 — 갱신 후 깨지지 않게

색 토큰 갱신 방식이 영리해서, 갱신 후에도 모든 자료가 그대로 작동합니다.

어떻게 호환성을 유지했나

  • 기존 변수명 (`--ink`, `--teal` 등) 그대로 유지 — 모든 CSS 규칙이 깨지지 않음
  • YUV `--yp-*` 토큰은 새로 추가 — :root 블록 상단에 표준 토큰을 함께 정의
  • 두 변수 시스템이 공존 — 새 코드는 `--yp-*`, 기존 코드는 그대로
  • YUV 검증 통과 — §9-1 "`--yp-*` 토큰 1순위" 기준 만족
이렇게 한 이유 각 자료의 모든 CSS 규칙(`var(--ink)` 같은 수백 줄)을 일일이 `var(--yp-ink)`로 바꾸면 위험성도 크고 시간도 오래 걸립니다. 두 변수 시스템을 공존시키는 게 YUV 표준도 따르고 자료도 안 깨뜨리는 가장 영리한 방법.
