5계층 매핑 + 한 곳에서 다 조정

연소사님이 한 화면에서 모든 사용자·콘텐츠·시스템을 자유롭게 조정할 수 있는 통합 관리 대시보드와, 그 위에서 작동하는 5계층 권한 구조를 정리합니다. YUV 3.2의 학원 중심 4계층 위에 연라이프 마을 구조를 자연스럽게 얹었어요.

합의된 결정

5계층 + 두 가지 가입 경로 + 통합 관리 대시보드

5계층: 서버관리자(연소사) → 학원관리자 → 마을지기 → 글지기 → 일반 주민

두 경로: 학원·학교 단위 가입(6자리 코드) ↔ 마을 직접 가입(이메일·비번) — 둘 다 결국 "일반 주민"으로 합류

통합 관리: 연소사님이 단 한 화면에서 모든 사용자·콘텐츠·AI·보안·시스템을 조정. 역할 승강·권한 토글·일괄 작업 모두 가능.

2. 두 가지 가입 경로 — 같은 "일반 주민"으로 합류

YUV의 학원 중심 흐름과 연라이프의 마을 흐름이 자연스럽게 합쳐집니다.

┌─ 경로 A: 학원·학교 단위 가입 (YUV 표준) ─────────────────┐ │ │ │ 연소사 (서버관리자) │ │ │ 6자리 코드 발급 │ │ ▼ │ │ 학원 관리자 │ │ │ 6자리 코드 발급 │ │ ▼ │ │ 학원 학생 → 연라이프 입장 = "일반 주민" │ │ │ └──────────────────────────────────────────────────────────┘ ┌─ 경로 B: 마을 직접 가입 (연라이프 고유) ─────────────────┐ │ │ │ 누구나 │ │ │ 이메일·비번 가입 │ │ ▼ │ │ 일반 주민 │ │ │ 운영자가 인증 (활동·신뢰도 보고) │ │ ▼ │ │ 글지기 ──── 마을지기 (선임 인증 시) │ │ │ └──────────────────────────────────────────────────────────┘ → 두 경로 모두 같은 "일반 주민" 자리로 출발 → 활동·인증에 따라 위 계층으로 승급 → 모든 사용자는 같은 `y_accounts` 통합 계정 DB → 연소사는 어느 경로로 들어왔든 모두 통합 관리
핵심 — 합류 지점이 "일반 주민" 학원 학생이 연라이프 마을에 들어오면 그도 일반 주민이 됩니다. 학원 활동(연플래너 등)은 학원 관리자가, 마을 활동(광장·블로그)은 마을지기가 봅니다. 한 사람이 두 자리에 동시 속하지만 권한이 충돌 없이 깨끗하게 분리.

6. 권한 누수 방지 — YUV §2-3 그대로

  • 일반 주민 화면에 글지기 기능 ❌ — 칼럼 작성 메뉴 안 보임
  • 글지기 화면에 마을지기 기능 ❌ — 모더 도구 안 보임
  • 마을지기 화면에 학원 관리자 기능 ❌ — 학원 가입자 데이터 안 보임
  • 학원 관리자 화면에 다른 학원 데이터 ❌ — 자기 기관만
  • 그 누구도 서버 관리자 화면 못 봄 — 연소사 외 접근 불가
  • "API"·"토큰" 단어 일반 화면 노출 ❌ — YUV 절대 규칙

7. 데이터 구조 — y_accounts 통합 (YUV §3·§10 준수)

// Firebase Firestore — y_accounts 컬렉션 (YUV 통합) { "uid": "...", "y_user_no": 1234, // 가입 순서 일련번호 "role": "general_resident", // 5계층 중 하나 "role_levels": { // 보조 역할 (병행 가능) "is_writer": false, // 글지기인가 "is_village_keeper": false, // 마을지기인가 "is_academy_admin": false, // 학원 관리자인가 "academy_id": null // 학원 ID (학원 가입 경로면) }, "join_path": "village" | "academy", // 가입 경로 "name": "임선생", "id": "lim-teacher", "pw_hash": "...", // bcrypt만 — 평문 X "code": null | "123450", // 6자리 코드 (학원 경로만) // 권한 추가 토글 (연소사가 자유롭게 조정) "extra_permissions": { "can_post_column": true, // 칼럼 작성 "can_moderate": false, // 모더 권한 "can_verify_journal": true, // 시민저널 검증 "shop_enabled": true // 가게 운영 }, // 감시·경고 "warning_level": 0, // 0/1/2/3 "on_watchlist": false, // 변경 이력 (불변 로그 별도 컬렉션) // ... "verification_status": "verified", "created_at": "...", "last_login": "..." }
핵심 — role + extra_permissions 두 단 역할(role)은 큰 분류, extra_permissions는 세부 토글. 연소사가 "이 사람은 일반 주민이지만 시민 저널 검증 권한은 줘봐도 좋겠다" 같은 미세 조정이 가능합니다. 모든 토글이 통합 대시보드에서 한 번 클릭으로 조정.

8. 구현 단계 — 어디에 끼울까

이미 짜둔 로드맵 안에 자연스럽게 들어갑니다. 별도 작업 추가 X.

주차기존 작업이번 합의 반영
1주차 기초 + 비용 패널 + y_accounts 5계층 스키마 셋업
+ 통합 대시보드 메뉴 골격 (한눈 보기)
2주차 모더 시스템 + 사용자 관리 페이지 (검색·필터·역할 변경)
+ 마을지기 권한 부여 기능
3주차 챗봇 + 메가 메뉴 + 글지기 자격 인증·승급 흐름
+ 학원 관리자 등록 (학원 가입 경로 시작)
4주차 다듬기 + 안전망 + 일괄 작업·메시지 발송
+ 모든 시스템 설정 통합 패널
5주차 자동 업데이트 (YUV §18 신설) + 학원 가입자와 마을 가입자 통합 보기 검증
정리

"한 곳에서 모든 것을 자유롭게" — 약속이 토대가 됩니다.

5계층 + 두 가지 가입 경로 + 통합 대시보드가 정해지니, 이전에 검토 사항으로 미뤄둔 모든 자료가 이 위에 자연스럽게 얹힙니다.

다음 갱신 자동 대상:

· AI 도입 4주 로드맵 — 통합 대시보드를 1주차에 추가

· 보안 가이드 — 5계층 권한으로 갱신

· 비용 모니터링 패널 — 통합 대시보드의 한 메뉴로

· 모더레이션 시스템 — 마을지기·학원관리자 권한 분리

· 데이터 구조 — y_accounts 5계층 스키마

다음 단계 제안 — 위 우선순위 1번(맥락 매핑)이 끝났으니, 우선순위 2번(색 토큰 일괄 갱신)부터 진행하면 모든 자료가 YUV 3.2 부합으로 정돈됩니다.

검토 사항 목록 — 한 단계 정돈됨

  1. 디자인 적용 (진행 중)
  2. YUV 3.2 부합 — 매핑 합의 ✓ 완료 (이번 결정)
  3. 색 토큰 일괄 갱신 ← 다음 작업 (반나절)
  4. 챗봇 엔진 Gemma 4 26B 전환 + 관련 자료 5개 갱신 (1일)
  5. 호스팅 전환 GitHub Pages → Cloudflare Pages (1~2주)
  6. 자동 업데이트 시스템 추가 (3~5일)
  7. SSO + Firebase 전환 (2~3주)
  8. 위 전부 위에 — 스크랩·폴더·내보내기 9주 작업
