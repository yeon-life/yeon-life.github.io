자동으로 뉴스가 흘러 들어오는 마을

연라이프 홈페이지의 7개 뉴스 카테고리에 자동으로 소식이 채워지게 만드는 방법. 본인 컴퓨터 없이, 무료로, 매시간 자동으로 실행되는 시스템을 그릴 수 있습니다. 현 상황(GitHub Pages + AI 도입 예정 + 새벽의 신뢰 결)에 맞춰 최적 길을 정리합니다.

한 페이지 결론

GitHub Actions 매시간 + RSS 수집 + AI 요약 + JSON 커밋

왜 이 방식 — 본인 컴퓨터 0% 사용, 완전 무료(공개 저장소), 이미 GitHub Pages 쓰고 있어서 자연스럽게 들어맞음, 가져온 뉴스를 Git 히스토리로 영구 보존, AI 요약과도 자연스럽게 결합.

비용 — 모두 무료. GitHub Actions는 공개 저장소(y-life.kr이 그렇음)에서 무제한 사용. AI 요약 추가하면 월 1~3천 원 정도.

운영 부담 — 한 번 셋업 후 거의 자동. 매월 1회 점검(소스 죽었는지) 정도면 충분.

1. 세 가지 자동화 방법 비교

★ 추천
GitHub Actions

스크립트가 매시간 깃허브 서버에서 자동 실행, 결과를 저장소에 커밋

장점 · 완전 무료 (공개 저장소)
· 이미 깃허브 쓰고 있음
· 히스토리 영구 보존
· 셋업 단순 (YAML 한 파일)
대안 1
Cloudflare Workers + Cron

매시간 자동 실행, 결과를 D1 DB에 저장, 사이트가 API로 조회

장점 · 무료 한도 큼
· AI 통합과 자연스럽게 연결
· 더 자주 실행 가능 (분 단위)
· API 응답 빠름
대안 2
n8n / Make.com

시각적 워크플로우, 클릭으로 연결, 코드 없음

장점 · 코드 없이 시각적 셋업
· 다른 서비스와 연결 쉬움
· 프로젝트 지침에 이미 언급
· 디버깅 쉬움

왜 GitHub Actions를 추천하는가

  • 이미 GitHub에 있음 — y-life.kr이 GitHub Pages로 호스팅되어 있으니 같은 저장소 안에서 깔끔히 마무리
  • 커밋 히스토리 — 어제·일주일 전·한 달 전 뉴스를 그대로 다시 볼 수 있음 (Git이 자동 백업)
  • 완전 무료 — 공개 저장소는 GitHub Actions 무제한
  • 실패하면 알림 — 뉴스 수집 실패 시 GitHub에서 자동 이메일 알림
  • JSON 파일 기반 — 사이트가 별도 DB 없이 JSON만 읽으면 됨. 단순하고 빠름.

3. 시스템이 어떻게 흘러가나

매시간 일어나는 일

  1. 매시 정각, GitHub Actions가 자동으로 깨어남
  2. Node.js 스크립트가 7개 카테고리의 RSS 피드를 동시 수집
  3. 각 피드에서 최신 5건씩, 총 35건 추출
  4. 중복 제거 (같은 기사가 여러 매체에 있을 수 있음)
  5. (선택) Gemini Flash로 한 줄 요약 자동 생성
  6. (선택) 자극적 기사 자동 필터 (광장 정서에 맞지 않는 것)
  7. 결과를 data/news.json 파일로 저장
  8. 저장소에 자동 커밋 → GitHub Pages가 즉시 반영
  9. 사이트가 news.json을 fetch해서 화면에 표시

실제 코드 흐름 (간단 버전)

// .github/workflows/news-update.yml name: 매시간 뉴스 자동 수집 on: schedule: - cron: '0 * * * *' # 매시 정각 workflow_dispatch: # 수동 실행도 가능 jobs: fetch-news: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: '20' - run: npm install rss-parser - run: node scripts/fetch-news.js env: GEMINI_KEY: ${{ secrets.GEMINI_API_KEY }} - uses: stefanzweifel/git-auto-commit-action@v5 with: commit_message: "📰 뉴스 자동 업데이트"
// scripts/fetch-news.js (핵심 부분만) const Parser = require('rss-parser'); const fs = require('fs'); const SOURCES = { '우리동네': ['https://www.ulsan.go.kr/rss/...', '...'], '지역': ['https://www.busan.com/rss/...', '...'], '대한민국': ['https://www.yonhapnews.co.kr/rss/...'], // ... 나머지 카테고리 }; async function main() { const parser = new Parser(); const result = {}; for (const [cat, urls] of Object.entries(SOURCES)) { const items = []; for (const url of urls) { const feed = await parser.parseURL(url); items.push(...feed.items.slice(0, 5)); } // 중복 제거, 정렬, AI 요약 등 처리 result[cat] = items.slice(0, 5); } fs.writeFileSync('data/news.json', JSON.stringify(result, null, 2)); } main();

4. AI와 결합하면 더 좋은 점

원문 그대로 가져오면 제목이 자극적이거나 길 수 있어요. AI를 한 번 거치면 "연라이프 톤"으로 정리된 한 줄 요약이 만들어집니다.

AI가 하는 일

  • 한 줄 요약 — 30자 내외로 핵심 압축
  • 광장 톤 변환 — 자극적 표현 → 차분한 표현 ("충격!" → "주목할 만한")
  • 카테고리 재분류 — RSS 분류가 어색하면 AI가 7개 카테고리 중 알맞은 자리로 이동
  • 중요도 점수 — 마을 정서와 어울리는 기사는 위로, 가십성은 아래로
  • 스팸·광고 자동 제외 — 광고성 보도자료 자동 필터

AI 비용 예측

매시간 35건 × 24시간 × 30일 = 월 25,200건 처리. Gemini 2.5 Flash 기준:

  • 입력 ~300토큰/건 × 25,200건 = 7.5M 토큰
  • 출력 ~50토큰/건 × 25,200건 = 1.26M 토큰
  • 월 비용: 약 1,500~2,500원 (Gemini Flash 무료 한도도 활용 가능)

5. 알고 가야 할 위험·주의 사항

저작권 — 가장 중요 뉴스 본문 전체를 그대로 복사해서 게재하면 저작권 위반입니다. 제목 + 한 줄 요약 + 원문 링크 까지만 활용. 본문은 절대 복사 X. 이건 모든 뉴스 큐레이션 서비스의 기본 원칙입니다.
RSS 차단 가능성 너무 자주 요청하면 일부 사이트가 IP를 차단할 수 있어요. 매시간이면 안전, 분 단위는 위험. User-Agent를 정확히 표시하고, 동일 사이트에는 일정 간격(예: 5초)을 두고 요청.
RSS 피드 죽을 수 있음 일부 사이트는 시간이 지나면 RSS 주소를 바꾸거나 폐쇄합니다. 매월 한 번 점검 필요. 죽은 피드는 GitHub Actions 실패 알림으로 자동 감지됨.
자극적·정치적 기사 — 광장 정서와 어울리지 않음 뉴스 자동 수집은 편하지만, 광장의 결을 망가뜨릴 수 있습니다. AI 필터를 꼭 두세요. 특히 자극적인 사회면 기사, 갈등 조장 정치 기사는 자동 제외 권장. "차분한 신뢰감"이 연라이프의 정서임을 잊지 마세요.
운영자 한 줄 검토 옵션 완전 자동도 좋지만, 더 안전한 방법은 "AI가 골라온 뉴스를 관리자 대시보드에서 한 번 보고 게시하는" 반자동 흐름입니다. 운영자가 매일 5분만 투자하면 광장 정서를 지킬 수 있어요.

6. 1주 안에 작동시키는 로드맵

1일차 — RSS 소스 점검

  • 위에 정리한 7개 카테고리 RSS 주소가 실제로 살아 있는지 확인 (각 URL 직접 열어보기)
  • 죽은 주소 발견 시 대체 소스 찾기
  • 각 소스의 저작권 약관 확인 (대부분 RSS는 인용 허용)

2~3일차 — GitHub Actions 셋업

  • y-life.kr 저장소에 .github/workflows/news-update.yml 추가
  • scripts/fetch-news.js 작성 (위 코드 참고)
  • 로컬에서 한 번 테스트 (Node.js로 직접 실행)
  • GitHub에 푸시 후 Actions 탭에서 수동 실행 → 결과 확인

4~5일차 — 사이트 연결

  • 기존 사이트의 뉴스 섹션이 data/news.json을 fetch하도록 수정
  • 로딩 상태·에러 처리 추가
  • 리디자인 단일 파일의 뉴스 자리에도 동일하게 적용

6~7일차 — AI 요약·필터 추가 (선택)

  • Gemini API 키를 GitHub Secrets에 추가
  • fetch-news.js에 AI 요약 단계 추가
  • 자극적 기사 필터 프롬프트 작성·테스트
  • 관리자 대시보드에 "오늘의 뉴스 검토" 메뉴 추가 (선택)

7. 같은 방식으로 더 할 수 있는 일

한 번 GitHub Actions 자동화 패턴을 익히면 다른 곳에도 응용할 수 있어요.

매주 자동 — 화두 후보 생성

매주 일요일 자정에 자동으로 "이 주의 화두 후보 10개"를 AI가 생성 → 관리자 대시보드에 띄움 → 운영자가 한 개 골라 게시.

매일 자동 — 광장 활동 요약

매일 새벽 6시에 어제 광장 활동(글·댓글·좋은 물음) 요약 → 운영자에게 이메일 발송.

매월 자동 — 백업

매월 1일에 사이트 전체 데이터를 압축해 Google Drive로 자동 백업.

이벤트 자동 — 시민 저널 6단계 검증 알림

새 검증 단계 완료 시 자동으로 다음 검증자에게 알림 발송.

8. 정리 — 검토 사항 목록에 추가

지금은 디자인 마무리 단계이니 즉시 시작할 일은 아니지만, 다음에 돌아왔을 때 함께 진행할 검토 사항으로 남겨둡니다.

이미 정리된 검토 사항과 함께

  • 1. AI 챗봇·모더레이션 도입 (4주 로드맵)
  • 2. 보안 강화 (5가지 핵심 + 감시·3단계 경고)
  • 3. 자동 뉴스 수집 시스템 (이번 항목)
  • 4. 디자인 적용 (리디자인 단일 파일 → 운영 사이트)

네 가지를 함께 진행하면 좋은 이유

이 네 가지는 같은 인프라(Cloudflare Workers + GitHub Actions + Gemini/Claude API)를 공유합니다. 한 번 셋업하면 네 가지 모두에 활용되니, 디자인 끝나고 한꺼번에 시작하는 게 가장 효율적입니다.

한 줄로

GitHub Actions + RSS + (선택) AI 요약 → 매시간 자동 갱신

본인 컴퓨터 0%, 비용 0~3천원/월, 한 번 셋업 후 거의 자동. 디자인 마무리 후 다른 검토 사항들과 함께 진행하시면 됩니다. 그때까지는 이 문서를 검토 사항 자료로 두고, 결정만 하셔도 좋습니다.
