3단 폴더 + 바로가기 — 정밀한 정리

폴더 깊이를 3단으로 늘리고, 핵심 키워드 추출로 가장 어울리는 자리 한 곳에 원본을 두고, 다른 비슷한 자리에는 바로가기(화살표만 있는 가벼운 링크)를 둡니다. 복사하지 않습니다. 한 별은 우주에 하나, 다른 자리에선 그것을 가리킬 뿐.

설계 원칙

"한 별은 우주에 하나, 가리키는 화살표는 여러 개"

스크랩한 글·내용은 딱 한 곳에만 실제로 저장됩니다 (= 원본). 다른 폴더에 보이는 것은 원본을 가리키는 화살표일 뿐이에요 (= 바로가기).

원본을 수정하면 모든 바로가기에서 즉시 반영. 바로가기를 지워도 원본은 그대로. 원본을 지우면 모든 바로가기가 함께 사라짐.

이건 컴퓨터의 심볼릭 링크·윈도우 바로가기와 같은 원리입니다.

013단 폴더 깊이

이전 2단에서 3단으로 확장. 가장 적당한 균형이에요 — 너무 얕으면 자료가 뭉치고, 너무 깊으면 길을 잃습니다.

단예시역할최대 개수
1단철학·사상큰 갈래7개
2단철학·사상 / 자유의지중간 갈래5개 (각 1단 안)
3단철학·사상 / 자유의지 / 리벳 실험구체 주제5개 (각 2단 안)

이론상 최대 7 × 5 × 5 = 175개 폴더지만, 실제로는 사용자당 30~50개면 충분합니다.

02AI 핵심 키워드 추출 — 어디에 원본을 둘까

스크랩한 순간 AI가 그 문장에서 가장 중요한 키워드를 뽑아내고, 그 키워드가 가장 어울리는 3단 폴더 한 곳을 "원본 자리"로 정합니다.

[스크랩 내용] "의식과 행위 사이 0.3초의 간극이 우리에게 던지는 질문은 자유의지의 부정이 아니라, 다른 종류의 자유에 대한 초대가 아닐까." ↓ AI 분석 (Gemini Flash) [추출된 키워드 — 가중치 순] ① 자유의지 (0.94) ← 핵심 키워드 ② 리벳 실험 (0.86) ③ 의식·행위 (0.71) ④ 멈춤·자유 (0.58) ↓ 폴더 매칭 [원본 자리 — 1곳] 📁 철학·사상 / 자유의지 / 리벳 실험 ← 가장 좋은 자리 [바로가기 후보 — 비슷한 자리] 📁 철학·사상 / 자유의지 / 노자 계열 (유사도 71%) 📁 교실의 순간들 / 수업 단상 / 윤리 수업 (유사도 65%) ↓ 모달 표시 "원본은 [리벳 실험]에 두고, 두 곳에 바로가기 둘까요?" 📁철학·사상 24

◐ "의식 이전의 행동" 원본

위 예시 — "선택이라는 말의 무게"는 단 하나의 원본이지만, 세 곳에서 보입니다. 원본 한 자리 + 바로가기 두 자리.

04시각 구분 — 원본과 바로가기

원본 — 진짜 별

딥 틸 테두리, 채워진 별

원본
"의식과 행위 사이 0.3초의 간극이 우리에게 던지는 질문은 자유의지의 부정이 아니라..."
📁 철학·사상 / 자유의지 / 리벳 실험

진짜 자료가 여기 있음. 클릭하면 편집 가능.

바로가기 — 가리키는 화살표

호박색 점선, 화살표 아이콘

바로가기
"의식과 행위 사이 0.3초의 간극이..."
원본 위치 ↗ 철학·사상 / 자유의지 / 리벳 실험

읽기는 똑같이 됨. 클릭하면 원본 자리로 이동.

시각 차이의 핵심

  • 원본 — ◐ 채워진 별 + 딥 틸 실선 테두리
  • 바로가기 — ↗ 화살표 + 호박색 점선 테두리
  • 호버 시 — 바로가기에 마우스 올리면 "원본은 [철학·사상 / 자유의지 / 리벳 실험]" 작은 툴팁
  • 클릭 시 — 바로가기 클릭하면 원본 위치로 이동 + 강조 애니메이션

05동작 규칙 — 무엇을 하면 무엇이 바뀌나

동작원본에 미치는 영향바로가기에 미치는 영향
원본 내용 수정 즉시 갱신 모든 바로가기도 즉시 갱신
원본 삭제 사라짐 모든 바로가기도 함께 사라짐
바로가기 1개 삭제 그대로 (영향 없음) 해당 1개 자리에서만 사라짐
바로가기를 원본으로 승격 기존 원본이 바로가기로 강등 그 자리가 새로운 원본 자리
원본을 다른 폴더로 이동 원본 자리만 바뀜 바로가기는 그대로 (계속 가리킴)
새 바로가기 만들기 그대로 새 자리에 가리키는 화살표 추가
가장 중요한 규칙 — "삭제 확인" 원본을 지우면 모든 바로가기가 함께 사라집니다. 이건 큰 변화이므로 삭제 시 "이 별은 N곳에서 보이고 있습니다. 정말 다 지울까요?" 확인 모달 필수.

06데이터 구조 — 깔끔하게 한 자리

핵심: 스크랩 본문은 scraps 테이블에 딱 한 번만 저장. 폴더와의 관계는 scrap_folders 테이블에 is_primary 플래그로 구분.

// 스크랩 본문 — 한 자리에만 저장 CREATE TABLE scraps ( id TEXT PRIMARY KEY, user_id TEXT, content TEXT, -- 실제 본문 (한 번만!) source_type TEXT, -- news/plaza/chatbot/blog/self source_url TEXT, my_note TEXT, primary_keyword TEXT, -- AI가 뽑은 핵심 키워드 embedding BLOB, -- 임베딩 벡터 (검색·매칭용) created_at DATETIME ); // 폴더 (3단 깊이까지) CREATE TABLE folders ( id TEXT PRIMARY KEY, user_id TEXT, parent_id TEXT, -- NULL = 1단, 부모 있음 = 2·3단 depth INTEGER, -- 1, 2, 3 — 3 초과 불가 name TEXT, emoji TEXT, color TEXT, representative_vector BLOB ); // 스크랩-폴더 관계 (한 별이 여러 자리에 보일 수 있음) CREATE TABLE scrap_folders ( id TEXT PRIMARY KEY, scrap_id TEXT, -- 같은 별을 가리킴 folder_id TEXT, is_primary BOOLEAN, -- 🔑 핵심: TRUE면 원본, FALSE면 바로가기 added_by TEXT, -- 'ai_auto'|'ai_suggest'|'user' added_at DATETIME, UNIQUE(scrap_id, folder_id) -- 같은 폴더에 중복 X ); // 제약: 한 스크랩당 is_primary=TRUE 인 행은 정확히 1개 CREATE UNIQUE INDEX idx_one_primary ON scrap_folders(scrap_id) WHERE is_primary = 1;
저장 효율 스크랩 본문은 한 번만 저장됩니다. 바로가기를 100개 만들어도 추가되는 건 scrap_folders 테이블에 작은 행 한 줄(약 200바이트)뿐. 본문 자체는 복사 안 됨. 데이터베이스가 가벼워지고 수정·삭제도 깔끔해요.

07스크랩 → 원본 + 바로가기 한 번의 흐름

  1. 사용자 스크랩 → AI가 핵심 키워드 추출 + 폴더 매칭
  2. 모달 표시: "원본은 [A] 폴더에 두고, [B]·[C] 폴더에 바로가기 둘까요?"
  3. 옵션 A — 그대로 정리 (한 번 클릭) → 원본 1개 + 바로가기 2개 자동 생성
  4. 옵션 B — 원본만 (바로가기 만들지 않음) → 원본 1개만 저장
  5. 옵션 C — 내가 정하기 → 폴더 트리에서 직접 원본 위치 선택, 바로가기 자리도 직접 선택

나중에 추가하기

이미 원본이 있는 별을 다른 폴더에 추가하고 싶을 때:

  • 별 위에서 우클릭 (또는 모바일 길게 누름) → "다른 자리에 바로가기 두기" 메뉴
  • 또는 별을 다른 폴더로 드래그할 때 — Alt 키 누른 상태로 드래그하면 바로가기 생성, 그냥 드래그하면 원본 이동
  • "이 별은 어디에서 보이나요?" 메뉴 — 모든 자리 한눈에 표시

08AI 키워드 추출 — 더 정확하게

AI가 키워드를 뽑을 때 단순히 빈도수가 아니라 다음 기준을 함께 봅니다.

  • 전체 문맥 의미 — Gemini 임베딩으로 문장의 핵심 주제 파악 (단어 빈도 아님)
  • 본인의 다른 별과 비교 — 이미 모은 별과 어떤 별이 가장 비슷한지
  • 본인이 자주 쓰는 표현 — 본인 어휘 사전에 맞게
  • 원본 출처 — 광장 글이면 그 글의 카테고리도 힌트

09한계·제한 — 너무 많아지지 않도록

바로가기 개수 제한

  • 한 스크랩당 바로가기 최대 5개까지 (원본 1 + 바로가기 5 = 6자리 노출)
  • AI 자동 생성은 최대 2개까지 (나머지는 본인이 추가)
  • 그 이상 필요하면 "이 별은 너무 곳곳에 있어요. 진짜 필요한 자리만 두세요" 안내

폴더 깊이 강제 3단

  • 3단 폴더 안에는 별만 들어감 (4단 폴더 만들 수 없음)
  • 1단·2단 폴더에도 별을 직접 둘 수 있음 (3단 강제 아님)
  • 1단 7개 × 2단 5개 × 3단 5개 = 최대 175개 폴더 — 실제론 30~50개 권장

"바로가기를 또 바로가기로?" — 금지

심볼릭 링크의 흔한 함정. 우리는 단순화 — 바로가기는 항상 원본을 직접 가리킴. 바로가기의 바로가기는 만들 수 없음.

10비용 영향 — 무시할 만큼 작음

작업이전 (2단)지금 (3단 + 바로가기)
스크랩당 AI 호출1회 (폴더 매칭)1회 (폴더 매칭 + 키워드 + 바로가기 후보 한 번에)
월 추가 비용~1,500원~1,800원 (300원만 추가)
DB 저장본문 1번본문 1번 + 바로가기 행만 (총 +5% 정도)

3단 + 바로가기로 정밀도가 크게 좋아지지만 비용 증가는 거의 없음.

11갱신된 검토 사항

스크랩·폴더 시스템이 다음과 같이 최종 정리됩니다.

  1. 다섯 자리에서 스크랩 — 뉴스·광장·챗봇·블로그·내 메모
  2. AI 핵심 키워드 추출 — Gemini 임베딩으로 문맥 의미 분석
  3. 3단 폴더 자동 생성 — 큰 갈래 → 중간 갈래 → 구체 주제
  4. 원본 1자리 + 바로가기 여러 자리 — 복사 없음, 가리키는 화살표만
  5. 다섯 가지 보기 — 전체·폴더·별자리 지도·태그·타임라인
  6. 월간 자동 정리 — AI가 분할·병합 제안
  7. 2027 자서전 공방으로 이어짐
한 줄로

"본문은 한 번, 화살표는 여러 번."

스크랩한 글은 본인의 우주에 단 하나로 존재합니다. 그것이 여러 폴더에 보이더라도 실제로는 한 자리에만 살아 있고, 다른 곳은 그것을 가리키는 화살표일 뿐입니다.

덕분에 — 수정 한 번이면 모든 곳에 반영되고, 저장 공간은 가볍게 유지되고, 본인의 사유의 지형이 깔끔하게 정돈됩니다.

가지런하되 갇히지 않고, 풍성하되 무겁지 않게.
